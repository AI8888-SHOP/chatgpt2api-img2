# 1.2.2 · 独立需求优化与后台方案生成

## 用户界面

- 将“帮我完善需求并生成方案”拆为“优化需求”和“生成方案”。
- 优化只改写文字，先展示可编辑建议；支持采用、保留原文、撤销，不自动生成方案。
- 生成方案在后台执行，返回任务回执；页面查询进度，刷新后可恢复需求、素材与方案。
- PPT / PSD 使用各自的优化指令。PSD 文本优化不需要图片，但生成拆分方案仍须上传原图。
- 两套 A/B 主题与明暗模式继续保留，支持手机及桌面。

## 限额与可靠性

- 文本优化与现有绘图提示词优化共用 RPM、日次数、Token 预算和并发配额，仅供网页登录会话使用。
- 文本优化上游等待最多 30 秒、输入最多 2048 Token（含固定指令）、输出最多 512 Token；后台设得更低时遵循低值。
- 优化失败保留原文，可跳过；不创建方案任务、不扣生成积分、不消耗方案修改次数。
- 方案提交支持幂等回执、断网恢复、持久化队列与明确的超时失败状态，避免浏览器一直等待上游。
- 用户确认方案并制作文件时才扣生成积分，制作失败自动退款。
- 后台化不代表上游超时已消失；上游失败会在任务状态中显示。

## 升级与验收

- 镜像：`ghcr.io/ai8888-shop/chatgpt2api:1.2.2`。
- 保留已有 `config.json` 与 `data` 数据卷；新方案任务表按需创建，不清空用户、积分或历史文件。
- 前后端须一起升级：`POST /v1/editable-studio/plans` 现返回 HTTP 202 任务回执，不再直接返回最终方案。
- 已完成隔离验收：117 项后端测试、152 项浏览器检查、TypeScript 检查与 Node 22 生产构建。
- 浏览器测试使用合成上游响应；不将这些结果当作真实上游永不超时的保证。
- 回滚可切回 1.2.1 镜像并保留数据；回滚前须确认没有正在执行的方案或制作任务。
