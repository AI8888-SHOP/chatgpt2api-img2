# 1.2.3 · PSD 图层计数修复与制作流程审查

## 根因与修复

- 后台最大图层数与单次任务总图层数是两层限制。用户设 12、后台设 30 时，本次最多 12 层，包括渲染器自动添加的 1 个背景，即最多 11 个前景。
- 旧实现发送通用的 60 个前景条目 Schema，未明确传达“用户总层数减 1”，仅在 AI 返回后拒绝超额结果，错误地提示用户减少内容。
- 现在根据本次任务动态生成 Schema 与服务器指令；PPT 必须匹配请求页数，PSD 前景不超过总上限减 1。不强凑数量、不截掉额外图层，不悄悄放宽至管理员上限。
- 正式制作使用用户确认、手动编辑后的确切页数 / 前景层数；仍允许用户删除页面或图层。
- 若 AI 仍返回错误数量，给出实际前景数、含背景总数、本次上限与后台上限；后端拒绝不合格结果，方案阶段不扣生成积分。

## 同步加固

- 确认接口再次核对原始任务图层上限，避免手工构造请求绕过限制。
- 超时、HTTP 失败及无效 JSON 等无法确认用量的请求，按完整输出额度占用预算；正式制作不在用量未知时自动重试。生成失败沿用原有事务化、幂等退款。
- 方案依旧只调用一次上游，不为纠错隐式增加调用或扩大 Token 预算。已知用量的制作失败仍受管理员重试次数、总输出预算和截止时间约束。
- 前端拒绝空值、小数、超限页数 / 层数、越出画布的组合坐标以及空标题等无效确认，避免浪费请求。
- PPT 粘贴超过 5 条正文时保留完整输入，提交前明确提示；不再静默截断用户正文。

## 审查与验收范围

- 覆盖 PPT / PSD 的需求输入、优化、异步方案、恢复与幂等、确认、制作、原生文件校验、下载隔离、额度和退款；执行整个后端自动化测试集，不声称已证明整个仓库没有缺陷。
- 130 项后端测试通过：新增 2 / 12 / 30 / 60 总层数边界、12 层与后台 30 层组合、两种上游协议的动态约束、编辑后确切计数、超额零扣费、确认绕过拦截、未知用量及退款回归。
- TypeScript 检查和 Node 22 / Next 生产构建通过。191 项浏览器检查通过，覆盖 A/B 两套主题、明暗模式、320 / 390 / 1366 宽度、异常数值和坐标、输入保留与恢复。
- 真实配置的上游 API 使用隔离账号和合成素材验收，未操作客户任务或积分。PPT 3 页制作、原生文件与预览通过；PSD 12 层总上限 / 后台 30 层下制作通过，并校验合成像素与原图一致。
- 额外用 11 个独立圆形执行真实上游边界验收：方案 11 个前景，最终 PSD 原生文件精确 12 层（含背景）、每层有像素、合成像素与原图一致，确认接口重复提交只扣费一次、其他用户无法下载。
- 保留现有上游 Responses / Chat Completions 兼容方式：动态 Schema 放入服务器指令，服务端校验结果；未擅自要求自建上游启用原生严格结构化输出参数。
- AI 分割质量依赖原图；遮挡内容不可凭空恢复，文字仍为像素层。一次真实验收不能保证任意图片、任意上游输出都成功。
