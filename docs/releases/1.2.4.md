# 1.2.4 · 修复 PSD 重叠区域导致主体空层

## 根因

旧渲染器按 PSD 堆叠顺序反向抠图，并把已分配像素从后续图层中排除。
大范围装饰层的矩形可能同时覆盖局部主体，GrabCut 也可能将主体识别为其前景，
因此先处理的大范围装饰会取走主体像素，让后处理的主体变成空层。
这是像素归属错误，与上一次的总图层上限问题不同。

## 修复

- 解耦像素归属顺序和最终 PSD 堆叠顺序：先保护文字 / Logo，再优先处理较小的实际轮廓区域，宽泛区域使用剩余像素；最终文件仍按用户确认的图层顺序排列。
- 分割初始化固定随机种子，避免仅调整图层顺序就引入随机结果变化。
- 不修改用户确认的图层数、名称、轮廓或原始像素，不直接删除空层、不复制整图，也不降低最少有效像素阈值。
- 区分重叠后无独立像素、未识别到可见像素、接近整图等错误，并明确指出图层编号。
- 原生 PSD 重新打开后逐层检查应用蒙版后的可见像素；不能只检查原始通道或 has_pixels()。
- 保留输出合成像素核对、原生结构校验、运行资源与时间限制、失败退款机制。

## 验收

- 新增 6 项纯合成回归：大范围装饰覆盖主体、改变堆叠顺序、精确轮廓、文字保护、真实重复层仍拒绝、整图复制仍拒绝。
- 全量 136 项后端测试通过；此次未修改前端交互或上游 API 请求协议。
- 使用报告问题的原图与保存的确认方案做断网离线复现：旧算法主体无剩余像素；修复后按原方案生成 10 层 PSD（9 个前景与 1 个背景），全部前景层有独立可见像素、前景不重复占用像素、合成与原图一致。
- 客户图像、方案和产物不进入仓库、镜像或 CI。离线验收不会调用上游、创建客户任务或扣积分。
- 历史失败任务未保留当时 AI 细化响应，本次复现使用保存的确认方案；不声称重放了当时不可用的细化结果。
- 此修复解决重叠取像顺序问题，不承诺平面图能恢复原始隐藏图层，也不把透明光效分解称为原始图层还原。
