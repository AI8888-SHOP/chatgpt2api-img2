# upstream-ops 原生视频协议

后台视频模型选择 `upstream-ops · /v1/videos`，填写服务提供方确认的模型 ID 或公开别名。渠道地址填写网关地址或以 `/v1` 结尾的地址，密钥填写网关密钥。模型、渠道和密钥不自动配置，不升级上游服务。

创建发送 JSON `model,prompt,seconds,aspect_ratio,resolution`。首帧使用 `input_reference`，参考图使用 `images`，音频使用 `audios`。素材由本站上传接口存储，通过已配置的 HTTPS 素材公网地址提供直链，不向网关发送 Base64。音频必须由管理员明确开启。

原生协议模型可分别勾选参考视频、视频编辑、视频延长和 1080p。前端按所选模型展示选项，后端再次校验能力；未配置素材公网地址时不开放需要视频素材的功能。视频上传限定一个 MP4，50 MB、1–60 秒，服务器使用 ffprobe 校验。参考模式发送 `videos` 与 `omni_reference_task_type: reference`；编辑/延长发送 `edit` / `extend`，只接受一个视频且不混入图片、音频，同时省略比例、分辨率、尺寸字段以遵循原视频。界面的清晰度在编辑/延长时仅作为本站计费档位，不承诺强制改变输出尺寸。申请时长仍为1–15秒，不支持自动时长。

1080p 每秒积分在后台单独设置，默认480p价格的四倍；提交后锁定计费金额。勾选能力仅代表管理员确认上游模型支持，不能让不具备该能力的上游模型获得能力。

仅以创建响应 `id` 绑定原渠道及密钥。`completed` 不要求 URL，进入下载阶段；后端使用原密钥请求 `/v1/videos/{id}/content`。流式下载限制 200 MB、180 秒，ffprobe 校验后原子保存到 `data/video_results`，随后成功结算。下载失败不重新创建任务、不误退已生成视频的积分。下载重试间隔 60 秒；401/403/404/410 转管理员核对。查询按上游轮询提示等待，未知状态降至每五分钟查询，任务七天后转核对。

结果接口 `/v1/video-jobs/{id}/content` 支持鉴权 GET/HEAD，FileResponse 提供本地文件 Range 支持。浏览器以当前用户身份获取 Blob 后播放，无需向网关传递密钥。文件长期保存在数据目录，目前没有自动清理策略，应监控磁盘占用并纳入备份。上游诊断 ID 单独存入任务数据库，不作为任务 ID 使用。

集成依据用户提供的契约。上游文档声明鉴权下载及 HEAD 修复尚未发布；在上游部署完成前不能视为真实端到端验收通过。本次使用模拟上游验证，不发起付费生成。
